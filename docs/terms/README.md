# 약관 초안

Borderless Sellers 회원가입·알림 약관 초안입니다. 서비스 화면과 동의 저장에 연결했지만, 공개 전 법률 검토가 필요합니다.

## 배포 순서
아래 순서를 지켜야 합니다. 코드를 먼저 배포하면 약관을 찾을 수 없어 회원가입이 `503 FEATURE_NOT_READY`로 막힙니다.

1. `python -m backend.scripts.migrate_integration --apply`
2. `python -m backend.scripts.register_terms --apply` (먼저 `--apply` 없이 실행해 계획을 확인합니다)
3. API 배포

두 명령은 `.env`가 가리키는 DB에 적용됩니다. 로컬 DB는 `python -m backend.scripts.local_integration migrate`와 `seed`를 사용합니다.

## 약관 등록 규칙 (`register_terms.py`)
| 상황 | 동작 |
|---|---|
| 회원이 이미 동의한 알림 약관이 있음 | 새 알림 약관을 등록하지 않고 기존 약관을 유지합니다(`KEEP_EXISTING`). 바꾸면 기존 동의자가 안내 없이 발송 대상에서 빠지기 때문입니다. **이때 `notification-consent.md`를 고쳐도 화면에는 반영되지 않습니다**(화면은 DB의 기존 약관을 보여 줍니다). |
| 이미 동의받은 버전의 본문·제목이 문서와 다름 | 등록을 거부합니다. 새 버전 코드와 더 큰 정렬값을 `TERMS`에 추가하세요. 오탈자 정정처럼 같은 버전을 꼭 고쳐야 하면 `--force`. |
| 같은 종류에 정렬값이 같은 다른 버전이 있음 | 등록을 거부합니다. 현재 버전은 정렬값이 가장 큰 행이며, 버전 코드 문자열로 고르지 않습니다(`V10` < `V2`). 알림 약관이면 오류 문구가 `--replace-notification`을 안내합니다. |
| 의도적으로 알림 약관을 새 버전으로 바꿈 (`--replace-notification`) | 다른 알림 약관을 끄고(`DISABLE`, 행·동의 기록은 남김) 문서의 알림 약관을 현재 약관으로 둡니다. 계획의 `consents`는 이 전환으로 재동의가 필요해지는 회원 수입니다(지금 현재 약관의 동의자만 셉니다). 알림 약관에만 쓰고, 가입 약관의 정렬값 충돌은 그대로 거부합니다. |

알림 약관을 새 버전으로 바꾸면, 알림을 켜 둔 기존 동의자에게는 알림설정·알림함에 재동의 안내가 뜨고 다시 동의할 때까지 새 알림이 오지 않습니다.

### 알림 약관을 의도적으로 바꾸는 절차
1. `notification-consent.md`를 고칩니다. 이미 동의받은 버전(`TERMS_NOTIFICATION_V1` 등)을 바꾸는 것이면 `register_terms.py`의 `TERMS`에 새 버전 코드와 더 큰 정렬값을 추가합니다.
2. `python -m backend.scripts.register_terms --replace-notification`로 계획을 확인합니다. `DISABLE` 항목의 `consents`가 이 전환으로 재동의가 필요해지는 회원 수입니다.
3. 팀이 확인한 뒤 `python -m backend.scripts.register_terms --replace-notification --apply`로 적용합니다. 되돌리려면 끈 약관의 `enabled`를 다시 켜고 새 약관을 끕니다.

### 운영 DB(RDS) 적용 전 확인
RDS에는 이 문서 이전의 알림 약관(`TERMS_V1`, 정렬값 10)이 있을 수 있습니다. 적용 전에 반드시 `--apply` 없이 실행해 계획을 확인합니다.
- `KEEP_EXISTING`: 기존 알림 약관에 동의자가 있어 그대로 둡니다. 새 문서로 바꾸려면 위 절차를 팀이 정한 뒤 진행합니다.
- 정렬값 충돌 오류: 기존 알림 약관에 동의자가 없고 정렬값이 새 약관과 같습니다. 아무것도 바뀌지 않은 상태이므로, 새 약관으로 바꾸려면 `--replace-notification`으로 계획을 다시 확인한 뒤 적용합니다.

## 동의 저장
| 항목 | 저장 위치 |
|---|---|
| 이용약관, 개인정보 동의, 알림 약관 | `user_consent` (사용자, 약관 버전, 응답, 시각) |
| 약관 본문과 버전 | `service_option` (`SERVICE_TERMS`, `PRIVACY_TERMS`, `PRIVACY_POLICY`, `NOTIFICATION_TERMS`) |
| 만 14세 이상 | 가입 요청에서 확인만 하고 따로 저장하지 않습니다 |

## 약관 동의 테스트
1. `/signup`에서 입력을 마쳐도 체크박스 3개를 모두 선택하기 전에는 가입 버튼이 비활성인지 확인합니다.
2. **내용 보기**로 이용약관과 개인정보 동의 본문을 확인합니다.
3. 가입한 뒤 계정 설정의 회원정보에서 동의 날짜가 보이는지 확인합니다.
4. 알림설정에서 전체 알림을 켜면 알림 약관 창이 뜨고, 동의해야 켜지는지 확인합니다.
5. 화면 아래 푸터의 이용약관과 개인정보처리방침이 로그인 전후 모두 열리는지 확인합니다.

## 임시 비밀번호 메일 테스트
**준비**
1. 루트 `.env`에 `API_SMTP_*` 값을 넣습니다. 항목은 `backend/.env.api.example`에 있습니다. 앱 비밀번호는 저장소·PR·이슈에 올리지 말고 담당자에게 따로 받습니다.
2. [INTEGRATION.md](../INTEGRATION.md) 순서로 Docker, API, worker, 프론트를 켭니다. `.env`를 바꾼 뒤에는 API를 다시 켭니다.
3. http://127.0.0.1:5173 을 엽니다.

**순서**
1. `/signup`에서 필수 약관에 동의하고, 실제로 메일을 받을 수 있는 이메일로 가입합니다. 로컬 DB에만 저장됩니다.
2. 로그아웃하고 `/find-password`에서 가입한 이름과 이메일을 넣어 임시 비밀번호를 요청합니다.
3. 메일함과 스팸함에서 메일을 확인합니다.
4. 임시 비밀번호로 로그인되고, 이전 비밀번호로는 로그인되지 않는지 확인합니다.
5. 계정 설정에서 비밀번호를 바꾸고 새 비밀번호로 다시 로그인합니다.

**결과별 의미**
| 화면 | 의미 |
|---|---|
| 메일을 발송하지 못했습니다 | 발송 실패. 비밀번호는 이전 값으로 되돌아갑니다 |
| 임시 비밀번호 요청이 많습니다 | 요청 제한. 기본값은 10분 대기, 하루 5회입니다 |
| 임시 비밀번호를 발급할 수 없습니다 | 이름·이메일 불일치, 또는 이용할 수 없는 계정 |

## 약속과 구현이 아직 다른 부분
아래가 준비되기 전에는 약관을 공개하면 안 됩니다.

| 약관 내용 | 현재 코드 | 필요한 작업 |
|---|---|---|
| 회원 탈퇴, 탈퇴 후 1개월 뒤 파기 | 탈퇴 API 보류 (DEC-46), 파기 작업 없음 | 탈퇴·파기 구현 |
| 약관 도입 전 가입자의 동의 | 동의 기록 없음 | 다시 동의받을지 결정 |
| 가입 약관(이용약관·개인정보) 새 버전 | 기존 회원에게 재동의를 받는 화면 없음 | 새 버전을 낼 때 함께 구현 |
| 소셜 가입 동의 | 체크박스만 있음, 서버 보류 | 소셜 구현 시 가입 API와 같이 `signup_versions()` 검증·저장을 거치도록 연결 |
| 변경 이력 공개 | 없음 | 이전 버전 보기 |
| 주요 이슈·정기 리포트 알림 | main에 아직 없음 (PR #68) | PR #68 병합 |

## 팀 확인이 필요한 판단
1. **개인정보 동의 체크박스:** 작성지침은 계약 이행에 필요한 정보를 동의 없이 처리할 수 있는 항목으로 구분해 안내합니다. 요구사항(FR-301-06)은 필수 동의를 정하고 있어 초안은 요구사항을 따랐습니다.
2. **OpenAI 국외 이전:** 초안은 계약 이행을 위한 처리 위탁으로 적었습니다(제28조의8제1항제3호). 별도 동의가 필요한지는 법률 검토에서 확인합니다.
