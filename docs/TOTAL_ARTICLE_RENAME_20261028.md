# 기사 본문 컬렉션 이름 전환 — 2026-10-28

현재 네 출처의 본문 컬렉션은 `total_article`입니다. `backend/app/services/news_collections.py`의 `ARTICLE_COLLECTION`만 현재 이름을 관리합니다. 구형 이름의 상수·자동 폴백은 제공하지 않습니다.

> 이름 변경: `kotra_article`은 `total_article`로 변경되었습니다. 과거 시험 결과·로그·기준선은 당시 원본을 보존하고 이름 변경 설명만 추가했습니다.

## 적용 범위

- 크롤링·단신 작업본의 색인 생성, 검색, 출처 매핑, 단신 반환 검증, 세대 검증, 이관 및 평가 경로를 같은 현재 이름으로 맞췄습니다.
- 기존 전체 색인은 복사본에서 Chroma `modify(name=...)`를 수행했습니다. 생성한 새 세대에서 카탈로그·사전과 전체 ID·문서·메타데이터·벡터를 대조한 뒤 활성 포인터를 전환했습니다.
- 구형 직접 접근 색인도 별도 복사본에서 이름만 바꾸고 검증 후 원래 논리 경로로 전환했습니다. 전환 후 정상 읽기를 확인한 이전 색인은 삭제했습니다.
- 기존 3컬렉션·옛 문서 형식의 단신 5건 시험 색인은 과거 실행 자료입니다. 해당 자료를 현재 활성 공통 색인으로 사용하거나 현재 규격으로 검증했다고 표시하지 않습니다.

실제 전체 데이터는 기사 14,618건·청크 105,358개입니다. 세대 색인과 직접 접근 색인 각각 전체 ID·본문·메타데이터·벡터 해시와 표본 검색 결과가 변경 전후 같았습니다. 이름 변경·이관 확인의 재임베딩 및 유료 API 호출은 0건입니다. 전체 카탈로그의 기사 ID·출처·원천 ID·제목·발행일·URL·본문 해시를 로컬 MySQL과 대조했습니다.

네 출처 연결 시험은 실제 로컬 MySQL 트랜잭션 안의 합성 기사와 가짜 임베딩·요약 응답을 사용했습니다. 출처 필터, 사용자 차단, 문장별 근거, 동일 입력 재사용, 변경 입력의 부분 재임베딩과 다른 출처 보존을 검증했습니다. 시험 행은 롤백됐고 기존 11개 테이블의 행 수·해시가 같았습니다. 실제 기사 검색 품질 평가를 뜻하지 않습니다.

크롤링 작업본의 기존 MySQL 시험 3건에서 발견한 오래된 전제는 현재 출처별 뷰·트리거 선행 검증·출처 시드에 맞춰 수정했습니다. 실제 집계 정책·뷰·트리거 정의는 변경하지 않았습니다. 로컬 시험에 섞인 RDS 인증서 설정은 시험 프로세스에서만 로컬 설정으로 명시했습니다.

최종 대조 중 단신 작업본에서 공통 임베딩·키워드 세대 관리의 동시 변경을 확인해 보존했습니다. 해당 소스를 고정한 사본으로 회귀·RAG·로컬 MySQL·실데이터 읽기를 재검증했습니다. 공유 메모리 Chroma를 쓰던 키워드 복구 시험에는 이전 시험의 배열 메타데이터가 섞였으므로, 이 시험만 독립된 임시 영속 클라이언트로 격리하고 종료 후 정리하도록 보완했습니다. 키워드의 엄격한 데이터 검증은 유지했습니다. 최종 회귀는 469건 통과했고 고정 사본과 현재 코드·SQL 해시가 같습니다.

현재 기본 프로젝트 경로와 별도로 보존돼 있던 로컬 전체 실험 색인에서 활성 세대를 전환한 결과입니다. 프로젝트 DB 설정을 바꾸거나 운영 RDS·AWS 스케줄러로 전환한 작업은 아닙니다. 전체 서비스 통합·Windows·검색 Recall 평가는 별도입니다.

커밋·푸시·브랜치·Git 인덱스 작업은 수행하지 않았습니다. 기존 미커밋 수정사항은 이름 변경과 위 시험 보완을 제외하고 유지했습니다.
