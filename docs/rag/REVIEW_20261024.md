# 기사 RAG 코드 재검토 기록

검토 기준: 사용자가 확정한 8단계 구현 계획과 `IMPLEMENTATION_PLAN.md`. 2026-10-24 구현 코드를 대조하고 아래 문제를 수정했다. 수집 범위·필터·검수 기준은 변경하지 않았다.

## 확인한 문제와 수정

| 문제 | 재현 조건·영향 | 수정 및 검증 |
|---|---|---|
| 목표 건수만 채우면 검색 종료 | 한 컬렉션 앞부분이 차단 기사로 채워지고 다른 컬렉션에서 5건이 나오면, 첫 컬렉션의 다음 순위에 있는 더 좋은 기사를 놓침 | 컬렉션별 조회 마지막 거리와 통합 최하위 거리를 비교해 추가 조회. 차단 14건 뒤의 15~19번 기사가 선택되는 사례 검증 |
| 이전 키워드가 현재 주제어 변경을 가림 | 본문은 그대로이고 기사 태그만 변경되면 이전 색인의 원래 키워드가 최종 주제어·차단 판단에 사용됨 | 현재 태그를 최종 주제어 기준으로 사용. 원래 키워드는 현재 주제어에 연결되는 구체어 복원에만 사용. 네 출처의 태그 변경 검증 |
| 오래된 원본이 일치하는 이전 보조 정보를 가림 | 새로 읽은 원본 본문이 저장 본문과 다를 때 일치하는 이전 본문 확인 정보까지 버림 | 여러 보조 정보 중 저장 본문이 일치하는 항목 선택. 불일치 입력으로 본문 상태를 추정하지 않음 |
| 캐시 장애가 정상 요약을 실패로 바꿈 | 캐시 경로에 파일이 있거나 읽기·쓰기 권한 문제가 발생 | 캐시 오류는 실행 추적에 남기고 검증된 요약 유지. 불필요한 모델 재호출 없음 |
| 저장 벡터의 내용 손상을 검출하지 못함 | 차원·유한성은 맞지만 저장된 벡터 값이 달라짐 | 배치별 입력 벡터와 저장 벡터 대조. 손상 시 교체 거부, 이전 활성 버전 유지, 재실행 성공 검증 |
| 중단 전 진행 상황이 디스크에 남지 않음 | 배치 처리 후 프로세스 중단 | 처리 건수·현재 컬렉션·배치 위치·단계를 배치마다 저장. `KeyboardInterrupt` 주입 시 이전 색인 검색 가능 여부 검증 |
| 캐시·추적 저장 시간이 전체 상한에서 빠짐 | 검색 완료 직후 파일 기록 중 전체 마감 시각 초과 | 응답 반환 직전에도 전체 마감 확인. 추적 기록이 지연되면 공통 종료 예외 전달 |
| 확정 품목·대표어에 대한 사전 확장이 불완전 | 질문에 별칭이 없고 확정 품목명이나 대표어만 있음 | 질문과 확정 품목명을 함께 기준으로 동의어·상위어·구체어 확장. 분야는 제외 조건으로 사용하지 않음 |
| 평가에 미확정 조건이 추가됨 | 현지 이슈 질문 또는 정답 출처 구성이 특정 출처에 집중된 검수 셋 | 챗봇 전용·정답 출처 할당 조건 제거. 50문항의 문항별 Recall@5 평균 판정 유지. 출처 범위는 별도 보고 |
| 재구성 색인 조회 시 현재 검색 코드를 사용 | 보존 코드로 만든 색인을 변경된 코드로 기준선 측정할 가능성 | `capture-legacy --snapshot`으로 보존한 코드 해시 확인·실행. 재구성 여부를 실행 설정에 기록 |

0 벡터 질문 임베딩은 정상 0건으로 처리하지 않는다. 실제 미검수 Holdout은 모델 호출 전에 거부한다.

## 검증 결과

- 공통 계약·검색·색인·근거·평가 도구 및 기존 기사·단신: **128개 통과**.
- 신문사 예약 작업·태그: **43개 통과**.
- 합계 **171개**. 재검토에서 회귀 테스트 11개를 추가했다.
- 실제 모델 대신 가짜 모델, 합성 기사, 임시 Chroma를 사용했다. 명령은 [사용 및 검증 문서](README.md#검증-명령)에 있다.

## 여전히 필요한 실제 검증

네 출처 전체의 실제 색인·검색·출처 표시, 재구성 기준선 측정, 사용자 정답 검수, 최종 50문항 Recall, 현지 이슈 20건, 대표 질문 20건 State, 의미·사실·인과관계 검수, 세 사용처의 실제 호출과 전체 서비스 성능 검증은 미완료다.

발췌가 원문에 포함되는지 확인하는 코드 검증은 의미적 정확성을 보증하지 않는다. 실제 서비스의 공통 그래프·호출 라우터 연결과 KOTRA 전체 수집·정제 예약 실행기 연결도 남아 있다. 테스트 통과를 최종 품질·서비스 통합 완료로 표시하지 않는다.
