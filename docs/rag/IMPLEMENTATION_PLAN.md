## 단신속보 평가 근거 정책 — 2026-10-29 사용자 확정

- 사용자 보고: 단신속보 기사 전체 URL 오류로 외부 원문을 직접 확인할 수 없다. 이는 사용자 제공 운영 제약이며 모든 URL에 대한 독립 접속 시험 결과를 뜻하지 않는다.
- 단신 Dev 검수·검색·요약 평가는 로컬에 저장된 기사 본문만을 근거로 진행한다. 외부 원문 접근이나 과거 원문 버전 확보를 일반적인 평가 진행의 선행 조건으로 요구하지 않는다.
- 저장 본문 전체를 읽고 근거 문단과 본문 버전을 고정한다. 제목·요약만으로 판정하거나 외부 지식으로 누락 내용을 채우지 않는다. 저장된 URL은 출처 식별 정보로 보존하되 링크 정상 접속을 검증했다고 표시하지 않는다.
- 발행일과 본문 내 출처 날짜가 다른 경우 차이를 기록한다. 저장 본문 기준의 적합성과 발행 당시 내용의 진위를 구분하고, 날짜를 임의 수정하거나 과거 버전을 확인했다고 표시하지 않는다. 기존의 원문 버전 확인 필요 상태는 외부 확인 불가·미확인 한계로 보존한다.
- 이전에 개별 보류한 문항은 별도 사용자 결정 없이 해제하지 않는다. 저장 본문 기반 질문·근거 승인은 전체 정답 목록 확정이나 Recall 합격을 뜻하지 않는다.
- 이 기준은 단신속보 평가에 적용하며, 다른 출처의 기준과 수집·필터 범위는 변경하지 않는다. 기준 변경 전 결과를 보존하고 비교 시 같은 질문·조건·본문 버전을 사용한다.

## 목표 — /plan에 사용할 내용

기존 기사 수집·정제·색인·단신 분석 코드를 재사용하여 KOTRA 해외시장뉴스, KOTRA 단신속보, 한국경제, 파이낸셜뉴스를 공통으로 검색하는 기사 RAG 모듈을 완성한다. 챗봇·현지 이슈·리포트가 같은 요청·응답 계약을 사용한다.

- `total_article`: 네 출처의 공통 본문 컬렉션. `source_code`로 KOTRA 시장뉴스·단신속보·한국경제·파이낸셜뉴스를 구분한다. 과거 `short_news`·`newspaper_article` 분리는 현재 실행·평가 계약에 사용하지 않는다.
- 기사 본문 색인과 공통 키워드 사전 색인의 범위를 분리한다.
- 질문과 호출자가 확정한 국가·HS4/HS6와 판본·기사 발행 기간으로 검색한다. 확정 조건을 유지하고 다른 분석의 결과를 검색 선행 조건으로 삼지 않는다.
- 온라인 기사 검색은 Chroma를 이용한다. 주제어·동의어·상위어·구체어를 활용하고 분야는 순위 보조에 사용한다. 분야 차이·미분류만으로 제외하지 않는다.
- 호출자가 전달한 정규화 차단 주제어를 기사 최종 주제어와 정확 일치로 비교한다. 차단 기사는 요약 전에 제외하고 모델에 전달하지 않는다.
- 네 출처를 통합하고 조건·차단·중복 제거를 적용한 고유 기사 수로 반환 건수를 계산한다.
- 챗봇은 상위 5건·기사별 1~2문장, 현지 이슈는 기본 5건·최대 7건, 리포트 현지 이슈는 3~5건이다. 적합한 기사가 부족하면 실제 건수만 반환한다.
- 주간 리포트는 직전 주 월~일을 사용하고 현지 이슈와 동일하게 기본 5건·최대 7건을 제공한다. 부족하면 실제 건수만 반환한다.
- 모든 원인 설명 문장에 원문 근거를 연결한다. 원문에 없는 사실·수치·인과관계를 추가하지 않고 근거가 부족한 설명은 보류한다.
- 결과 없음·결과 부족·근거 부족·부분 실패·전체 실패를 구분한다. 일반적인 RAG 실패 시 다른 정상 결과를 보존하며, RAG 담당 State 필드만 갱신한다. 전체 상한 초과는 공통 종료 정책을 따른다.
- 기존 수집 범위·필터·검수 기준을 변경하지 않는다.

최종 완료 기준은 네 출처의 색인·검색·출처 표시 연결, 실제 별도 최종 50문항의 문항별 고유 기사 Recall@5 평균 0.7 이상, 근거 기사 없는 원인 설명 문장 0건, 현지 이슈 20건 조건 검수, 대표 질문 20건 State 검수, 사용자 차단·중복 제거·갱신 실패 복구 검증, 세 사용처의 통합 및 전체 서비스 성능 검증이다. 기능 테스트 통과와 검색 품질·서비스 통합 완료는 각각 기록한다.

## 1단계 구현 범위와 남은 입력

구현한 파일:

- [요청·응답 계약](../../backend/app/schemas/rag.py): Pydantic 모델과 요청·응답 조건 일치 검증.
- [기준선 기록·평가 도구](../../backend/app/services/rag/evaluation.py): 기존 청크 검색의 기사 단위 기록, 지문 기반 입력 확인, 오프라인 Recall 진단, 기록 덮어쓰기 방지.
- [합성 요청·응답 예시](contract_examples.json): 여섯 처리 상태.
- [합성 평가 입력](evaluation_example.json): 네 출처 식별자를 포함하는 형식 확인용 4문항. 실제 정답셋이 아니다.
- [계약 테스트](../../backend/tests/test_rag_contract.py), [평가 테스트](../../backend/tests/test_rag_evaluation.py): 호출 조건·상태 일관성·근거 참조·청크 중복·실패/미실행·미판정 정답·Holdout 경계 확인.
- [연동 명세](README.md): 현재 코드와 메타데이터 제공 경로, 실행 방법, 계약 확인 항목.

프로젝트와 작업 자료에서 재사용 가능한 50문항 정답셋을 확인하지 못했다. 실제 기사와 정답을 임의로 만들지 않았다. 실제 기준선 측정에는 평가 질문·정답 기사 목록·정답 판정 기준·고정된 평가 색인 범위가 필요하다. 최종 Recall은 정답이 있는 별도 50문항의 문항별 평균으로 확정했다. 정답 없음은 별도 기능 검증이다. 주간 건수는 기본 5건·최대 7건으로 확정했다.

1단계 모델을 재사용해 2~7단계의 공통 색인·검색·요약·State 어댑터와 처리 연결 코드를 추가했다. 실제 서비스의 공통 그래프·호출 라우터 연결은 남아 있다. 계약 유효성은 원문 근거의 의미적 정확성이나 실제 검색 품질을 보증하지 않는다.

1단계 당시 검증 결과: 새 계약·평가 테스트 39개와 기존 기사·단신 관련 테스트 42개, 총 81개가 통과했다. 합성 평가 입력 CLI 검증, 요청·응답 JSON Schema 생성, 문서 내부 링크와 공백 검사도 통과했다. 테스트는 합성 입력·가짜 모델 호출을 사용했으며 실제 50문항 기준선과 검색 품질은 측정하지 않았다. 실행 명령은 [연동 명세](README.md)의 실행 방법에 기록했다.

## 2단계 이후 구현 결과와 남은 작업

- 신문사 국가는 언급 국가 태그를 사용하고, 품목은 검증된 HS 태그 또는 태그가 없을 때 본문 관련성으로 판단한다.
- 공통 기사 구조·사전 재사용·출처 분리·본문 색인·검증 후 세대 전환·벡터 재사용·실패 복구를 구현했다.
- 단일 컬렉션 통합 검색·정확 일치 차단·기사 단위 중복 제거·질문별 근거 요약·캐시·실행 추적을 구현했다.
- 주간 요청 계약과 예시를 기본 5건·최대 7건으로 수정했다. 신문사 응답에는 국가가 언급 국가임을 표시한다.
- 기존 KOTRA의 본문 누락 시 요약·제목 대체 경로를 확인했다. 일치하는 원본으로 본문 여부를 확인하지 못한 입력은 미확보 상태로 보존하고 본문 색인·요약을 보류한다.
- 2026-10-24 구현 후 기능 검증: 공통·기사·단신 117개와 신문사 34개, 총 151개 통과. 가짜 모델과 임시 색인을 사용했으며 실제 검색 품질 통과를 뜻하지 않는다.
- 신문사 예약 작업과 단신 기본 처리에 공통 색인 연결을 추가했다. KOTRA는 수집·정제 결과를 받는 연결 명령을 제공하며, 전체 수집·정제 예약 실행기와의 연결은 남아 있다.
- 기존 상태는 `data/rag/baselines/20261024_013843`에 보존했다. 기존 KOTRA 색인은 없어 재구성 실행 경로를 제공했으며 실제 재구성과 측정은 미완료다.
- 실제 기사로 Dev 10문항·최종용 50문항 초안을 만들었다. 현재 KOTRA 두 출처만 확보했고 정답은 모두 미판정이다. 신문사 자료 보완 후 사용자가 질문·정답을 검수해야 한다.
- 현재 기사 조회 연결이 완료되지 않아 실제 네 출처 전체 색인을 수행하지 못했다. 이후 사용자 승인으로 보존된 단신 5건에 한해 실제 모델 연결을 검증했다. 기존 로컬 색인을 새 운영 색인으로 전환하지 않았다.
- 실제 50문항 Recall, 현지 이슈 20건 적합성, 원문 의미·인과관계 검수, 대표 질문 20건의 실제 State, 세 사용처·전체 성능 검증은 미완료다.

## 구현 코드 재검토 — 2026-10-24

검색 조기 종료로 인한 순위 누락, 이전 키워드가 현재 주제어를 덮는 문제, 캐시 장애로 정상 요약이 실패하는 문제를 수정했다. 저장된 벡터 내용 검증·배치 진행 기록·최종 응답 시각 검증도 보강했다. 재구성 기준선은 보존한 검색 코드를 지정해 기록할 수 있도록 연결했다.

최종 평가의 챗봇 전용 제한과 정답 출처별 추가 조건을 제거했다. 확정한 50문항·문항별 평균 Recall@5 0.7 기준을 유지하고, 출처 범위는 별도 보고한다. 실제 Holdout은 검수 완료 전 실행하지 않는다.

재검토 후 공통·기사·단신 128개와 신문사 43개, 총 171개 테스트가 통과했다. 자세한 재현 조건과 남은 검증은 [코드 검토 기록](REVIEW_20261024.md)을 따른다. 실제 검색 품질·서비스 통합 미완료 상태는 유지한다.

## 검수 대기 중 진행한 작업 — 2026-10-24

- 기사 읽기 연결 재확인 결과 실패. 신문사 실제 자료 경로도 미확보다.
- 사용자 승인한 보존 단신 5건을 별도 경로에 본문 청크 6개로 색인했다. 같은 Dev 질문을 세 사용처의 RAG 계약으로 실행했다. 원문 발췌·국가·기간·다른 State 보존을 확인했고, 각 요청에서 근거 요약 1건과 나머지 후보의 보류를 기록했다. 다른 세 출처가 없어 모두 partial이다.
- 위 호출은 실제 서비스 그래프·라우터 연결 검증이 아니며, 의미·사실·인과관계는 사용자 검수 대기다.
- 20개 합성 상황의 State 어댑터 보존 검증을 완료했다. 실제 대표 질문 20건 State 검수는 남아 있다.
- Dev 10문항·최종용 50문항의 검수 입력을 만들고, 승인·원문 지문·발췌·기사 식별자·국가·기간을 확인해 정답셋으로 변환하는 도구를 추가했다. 현재 입력은 모두 pending이다.
- 이번 관련 회귀 테스트 134개가 통과했다. State 20개 상황은 이 중 하나의 매개변수화된 테스트에서 각각 검증했다.

실행 결과, 직접 검수할 문장, 준비할 자료와 다음 순서는 [사용자 검수·준비 안내](HUMAN_HANDOFF.md)에 정리했다.

## 실험과 후속 고도화

기존 검색을 기준선으로 보존하고 같은 Dev set에서 한 번에 한 조건만 변경한다. 실패 결과도 남긴다. Holdout은 최종 설정 확정 후 최종 검증에만 사용하며 데이터·청킹·평가 조건 변경 시 설명을 갱신한다.

필수 구현 이후의 고도화는 하이브리드 검색, 추가 재순위화 모델, 청킹 최적화, 추가 의미 검증 모델이다. 공통 사전 연결·단신 본문 검색·신문사 색인과 검색은 필수 구현에 포함된다.


2026-10-26 통합 보완: 평가 실행기와 합격 판정기가 같은 공통 컬렉션 계약을 사용하도록 맞췄다. 검수된 비합성 holdout 50문항·확정 설정·문항별 평균 Recall@5 0.7 기준은 변경하지 않았다. 과거 세 컬렉션 실행 기록은 현재 합격 판정 대상이 아니다.
