# Report Agent 질문 Holdout 평가

평가일: 2026-11-09 · 이슈 #82

**새 질문 24개를 고정한 뒤 `edd27bc`의 코드·프롬프트로 한 번만 실행했다.** 결과는 **21/24 (87.5%)**이며,
실패를 보고 코드·프롬프트·정답을 고치거나 다시 실행하지 않았다. 결과 원본은 [report_agent_holdout_result.json](evaluations/report_agent_holdout_result.json)이다.

정답은 AI가 작성했고 **사람 검토는 대기 중**이다([검토표](evaluations/report_agent_holdout_gold_review.md)).
실제 사용자 질문이나 독립 전문가가 만든 검증 세트의 성능은 아니다.

## 실행 격리와 고정 조건

- 실제 호출 평가([REPORT_AGENT_LIVE_EVALUATION.md](REPORT_AGENT_LIVE_EVALUATION.md))의 32문항과 같은 질문은 없다. 표현·국가·품목·기간을 새로 썼다.
- 정답 규칙은 실행 전에 정했다. 이전 조건을 이어받는 질문은 실제 호출 평가 2판과 같이 "비우거나 같은 값"을 인정한다(`inherit_equivalent`).
- 실행 전 평가 하네스를 커밋했다(`edd27bc`, 결과의 `harness.dirty = false`). 질문·프롬프트·스키마 해시는 [manifest](evaluations/report_agent_holdout_manifest.json)에 있다.
- [실행 잠금 기록](evaluations/report_agent_holdout_run_lock.json)이 있으면 다시 실행하지 않는다. 문항 안의 재시도(플래너 2회)는 운영 정책대로 적용했다.
- 모델 `gpt-4.1-mini`, 비용 추정 **$0.026**. 운영 RDS·DB는 쓰지 않았다(플래너는 DB를 읽지 않음).

## 실패 사례

- **H04 "최근 1년 대만 반도체 수출 리포트":** "최근 12개월"(`recent_months=12`)이 아니라 모델이 **임의의 과거 날짜(2023-06~2024-05)**를 기간으로 적었다.
  상대 기간을 절대 날짜로 바꾸면서 기준 시점을 잘못 잡은 것으로, 실제로 다른 기간의 리포트가 만들어질 수 있다.
- **H08 "조회해서 결과를 리포트로 남겨줘", H09 "예측한 다음 그 예측 결과로 리포트":** REPORT가 앞 결과를 가리키지 않았다.
  H08은 첫 시도에서 연결 순서가 잘못돼 스키마 검증("선행 질문은 현재 질문보다 앞에 있어야 합니다")에 실패했고, 재시도는 연결 없이 끝났다.
  실제 호출 평가의 발견 사항 1과 같은 동작이다.

## 해석

- 리포트를 만들지 말아야 할 질문, 수입 리포트, 여러 요청, 이전 대화 이어받기는 새 질문에서도 모두 맞았다.
- **결과 기반 리포트 연결**(실제 호출 평가 2/6, holdout 2/4)이 두 평가에서 공통으로 가장 약하다. 플래너 담당 범위의 개선 후보다.
- 상대 기간("최근 1년")의 날짜 환산 오류는 holdout에서 새로 드러났다. 실제 호출 평가에는 "최근 N개월" 표현만 있었다.
