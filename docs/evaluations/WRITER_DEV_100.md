# Writer Dev 100문항과 문항별 평가 기준

기존 Dev 6문항과 신규 94문항을 묶었다. 금액·통계·기사·대화 이력은 합성 자료다. 한 번호가 평가 1건이며 복합 질문의 하위 결론도 각각 채점한다. 아래에는 각 문항에서 실제로 물어본 질문, 답변에 필요한 사실, 실패 사례를 함께 표시했다.

## 채점 방법
- 두 JSONL 파일은 같은 `case_id`로 연결한다. 모델에 전달하는 자료는 입력 파일에 들어 있다. 평가자는 정답 파일의 `required_facts`와 `forbidden_claims`를 답변의 결론·설명과 대조한다. 사실의 맞고 틀림은 표현이 달라도 의미를 보고 판정한다.
- 자동 검사는 금액의 표시값, 비율의 크기, HS 코드, 요청된 인용 번호, 하위 질문 상태, 모델 호출 여부를 확인한다. 비율의 방향·비교 기간·인과관계·인용문이 실제 주장을 뒷받침하는지는 사람이 판정한다. 자동 검사를 모두 충족해도 의미 검수는 대기 상태로 남는다.
- 자동 채점기 점검에서 생성형 94문항에 “답변을 생략합니다.”를 넣은 결과, 의미상 실패인 94건 중 81건에 누락 경고가 발생했고 13건에는 경고가 없었다. 이 실험은 모델 성능 집계에서 제외한다.
- 단일 질문은 결론과 설명을 함께 본다. 복합 질문에서는 각 하위 결론의 근거와 수치를 해당 질문에 귀속해 검사한다. 결론에 필요한 문장 수와 설명 상한은 서비스의 일반·문장형 경로를 따른다.
- 결과 상태는 답변을 만들 재료의 충족도를 나타낸다. 예를 들어 검색 목표보다 기사가 적으면, 인용 가능한 기사가 있어도 부분 응답이 될 수 있다. `fixed`는 코드가 답하는 문항이며 모델 실패 후의 대체 응답과 따로 집계한다.

- 014·017·023은 금액의 증감 방향 또는 동일 여부가 맞으면 증감률 표기를 생략할 수 있다. 019는 9월 집계 여부까지 직접 밝혀야 한다. 073은 질문한 과거 수출액을 평가한다. 085·087·092에서 상대국 표현이 모호해도 질문 맥락과 금액이 일치하면 통과로 기록하고 표현 수정 의견을 남긴다.

## 로컬 사용

저장소 루트에서 아래 명령으로 100개 ID 쌍, 상태 스키마, 실행 경로, 근거 번호를 확인한다. API 키는 필요하지 않다.

```sh
python -m backend.scripts.evaluate_writer_dev --validate-only
```

실제 세 모델을 비교할 때는 `--env-file`과 새 `--output` 경로를 지정한다. 결과 JSONL에는 문항·모델별 초안, 시도별 사용량, 자동 검사와 의미 검수 상태가 기록된다. 이 표의 수치는 합성 입력의 기대값이다. 모델 실측 결과는 실행 후 별도로 집계한다.
