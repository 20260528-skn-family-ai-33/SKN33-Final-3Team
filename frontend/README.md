# Borderless Sellers 프론트엔드

2026.10.22 화면 목업 전체 반영본(`BorderlessSellers_화면목업_20261022_전체반영_키워드원본유지.html`)을 그대로 옮긴 React 프론트엔드입니다.
사용자 화면(BS01~BS31, BS24-1), 소셜 로그인·계정 찾기(LG02~LG13), 관리자 5개 메뉴(운영 현황·알림함·회원 권한·키워드·처리 이력)가 들어 있습니다.
목업의 색·글꼴·간격 클래스(`src/styles/mockup.css`)를 그대로 쓰고, 버튼·입력·탭·모달은 실제로 동작하게 만들었습니다.

데이터 수집 현황은 알림함의 데이터 수집 이력에서 확인합니다. 알림함은 운영 현황의 관리자 알림, 데이터 수집 이력(성공·실패·재시도), 회원 알림 전달 내역을 통합합니다. 재수집은 기존과 같은 시연 흐름이며 실제 수집 서버는 연결하지 않았습니다. 회원 검색은 유지하고 별도 검색 결과 탭은 제거했습니다.

## 실행하기

팀 레포(SKN33-Final-3Team)에서는 `frontend/` 폴더에서 실행합니다. Node.js 20.19 이상이 필요합니다(Vite 8 요구 사항).

```bash
cd frontend
npm install     # 처음 한 번
npm run dev
```

터미널에 나오는 주소(보통 http://localhost:5173)를 브라우저에서 엽니다. 끝낼 때는 터미널에서 Control + C.
React·Vite 외 추가 런타임 패키지는 없습니다.

## 소셜 로그인(카카오·네이버·구글) 설정

로그인 화면의 카카오·네이버·구글 버튼은 **실제 각 회사 로그인 페이지로 이동**합니다(OAuth 2.0 Authorization Code 방식).
키를 넣기 전에는 버튼을 누르면 설정 방법 안내 화면이 나옵니다.

1. 각 콘솔에서 앱을 만들고 아래 **Redirect(Callback) URI**를 그대로 등록합니다. 주소는 `localhost`로 맞추고, 개발 서버 포트는 5173으로 고정했습니다.

   | 제공자 | 콘솔 | 등록할 Redirect URI | 받을 값 |
   |---|---|---|---|
   | 카카오 | developers.kakao.com → 내 애플리케이션 | `http://localhost:5173/oauth/kakao` | REST API 키 (보안 탭에서 Client Secret을 켰다면 그 값도) |
   | 네이버 | developers.naver.com → Application 등록(네이버 로그인) | `http://localhost:5173/oauth/naver` | Client ID, Client Secret |
   | 구글 | console.cloud.google.com → API 및 서비스 → 사용자 인증 정보 → OAuth 클라이언트 ID(웹 애플리케이션) | `http://localhost:5173/oauth/google` | 클라이언트 ID, 클라이언트 보안 비밀번호 |

   - 카카오: 카카오 로그인 **활성화**, 플랫폼 → Web 사이트 도메인 `http://localhost:5173`, 동의항목 닉네임·카카오계정(이메일)
   - 네이버: 서비스 URL `http://localhost:5173`, 제공 정보 이름·이메일. "개발 중" 상태에서는 **멤버관리에 등록한 테스트 아이디만** 로그인됩니다.
   - 구글: OAuth 동의 화면을 만들고 "테스트" 상태라면 **테스트 사용자**에 로그인할 구글 계정을 추가합니다.
2. `frontend/` 폴더의 `.env.example`을 복사해 같은 폴더에 `.env`로 저장하고 값을 채웁니다(레포 루트의 `.env`는 백엔드용이라 개발 서버가 읽지 않습니다).

   ```bash
   cp .env.example .env
   ```

   `VITE_`로 시작하는 값(공개 ID)만 브라우저에 들어가고, `KAKAO_CLIENT_SECRET`·`NAVER_CLIENT_SECRET`·`GOOGLE_CLIENT_SECRET`은 개발 서버 안에서만 쓰입니다. `.env`는 `.gitignore`에 들어 있어 Git에 올라가지 않습니다.
3. `npm run dev`를 다시 실행하고 **http://localhost:5173** 으로 접속해 버튼을 누릅니다.

동작 순서: 버튼 → 제공자 로그인·동의 → `/oauth/{제공자}?code=…`로 복귀 → 개발 서버(`server/oauthDevApi.js`)가 code로 토큰을 받고 이름·이메일을 조회 → 이미 연결된 계정이나 같은 이메일 계정이면 메인으로, 처음이면 가입 마무리(LG05) → 관심사 등록. 취소·실패·위조된 요청(state 불일치)은 LG06 화면에 사유를 보여 줍니다.

**백엔드를 붙일 때**: FastAPI 등에서 `POST /api/auth/oauth/{kakao|naver|google}`(본문 `{ code, state, redirectUri }`)를 구현하고 `{ user: { providerId, email, name }, accessToken }`을 돌려주면 됩니다. 주소가 다르면 `.env`의 `VITE_AUTH_API_BASE`에 백엔드 주소를 넣습니다. 지금 회원 계정 저장은 브라우저(localStorage)에서 하므로, 실제 회원 DB·세션 발급은 백엔드에서 맡아야 합니다.

## 둘러보는 순서

1. **로그인(BS01)** → 메인(BS06). `전체 / 내 관심` 전환(BS07), 종 아이콘 알림 팝오버(BS13).
2. **회원가입(BS02)** → 관심사 등록 3단계(BS03~BS05) → 내 관심 메인.
3. **아이디 찾기(LG07)**: 이름 `홍길동` → 가입 계정 선택(LG08, 이메일 일부 가림) → 메일 전송(LG10). 없는 이름이면 LG09.
4. **비밀번호 찾기(LG11)**: `홍길동` + `honggd@example.com` → 임시 비밀번호 발송(LG12). 메일 미리보기의 임시 비밀번호로 실제 로그인됩니다.
5. **수출입 순위(BS08)**, **기사(BS09~BS12)**: 검색·탭·기간·페이지, 기사 `상세 보기`.
6. **AI분석(BS14·BS15)**: 조건 카드의 `리포트 생성` → 6단계 진행 → 완료 후 PDF·DOCX·엑셀. 입력창에 `미국 메모리 수출 추이와 이유를 알려줘`처럼 물으면 일반 답변·표 보기가 나옵니다.
7. **마이페이지**: 리포트 센터·구독(BS16~BS20, BS31), 알림설정과 약관 동의(BS22·BS23), 회원정보·탈퇴 사유(BS24·BS24-1), 비밀번호 변경(BS25), 관심정보(BS26), 알림함(BS27~BS30).
8. **관리자**(admin 계정): 운영 현황 → 회원 검색(아이디·이름) → 데이터 수집 실행 로그(터미널 원문) → 키워드·분류 체계에서 분야 지정·보류·새 분야 만들기 → 처리 이력.

화면설계서 번호별 주소는 `MOCKUP_MAP.md`에 있습니다.

## 서버 연결 전 범위

- 통계·환율·기사·AI 답변·관리자 수치는 **예시 데이터**입니다. 실제 수집·분석·메일 발송은 하지 않습니다.
- 계정·관심정보·채팅·리포트·알림·키워드 처리 결과는 브라우저 localStorage(`bs2.` 키)에 저장됩니다. 실제 개인정보는 입력하지 마세요.
- 관리자 화면(키워드·분류 체계 제외)은 목업 상태를 화면 단위로 옮긴 것이라, 버튼을 누르면 목업과 같은 다음 상태 화면으로 이동합니다.
- 서버를 붙일 때는 `src/store.jsx`(로그인·리포트 생성 등 동작)와 `src/data/*`, `src/admin/screens.js`(화면 데이터)를 API 응답으로 바꾸면 화면 코드는 그대로 쓸 수 있습니다.
