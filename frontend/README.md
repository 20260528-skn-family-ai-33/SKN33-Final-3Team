# Borderless Sellers 프론트엔드

기존 화면을 유지한 React 프론트엔드다. `src/main.jsx → AppProvider(store.jsx) → App.jsx → pages/`가 실행된다. 별도로 만들었던 `src/live/`와 `styles/live.css`는 제거했다. 기존 `mockup.css`, `app.css`, 이미지와 공통 레이아웃을 사용한다.

```powershell
npm ci
npm run dev -- --host 127.0.0.1
```

화면: http://127.0.0.1:5173. Vite가 `/api/v1`을 로컬 FastAPI 8000 포트로 전달한다. 설치·DB·Redis·worker 설명은 [연동 실행 안내](../docs/INTEGRATION.md), 파일별 변경 이유와 검증은 [검수 기록](../docs/INTEGRATION_REVIEW.md)을 참고한다.

## 연결 방식

- 로그인·관심사 등록·마이페이지·기사·순위는 기존 화면의 이벤트와 데이터만 API에 연결한다.
- `store.jsx`는 세션/관심정보/알림/구독/리포트를 서버에서 조회한다. 계정·비밀번호·서비스 결과를 localStorage에 저장하지 않는다. 예외로 관리자 알림(API-80)은 서버 읽음 저장소가 정해질 때까지 읽은 알림 ID만 브라우저에 임시 저장한다(`admin/useAdminAlertCount.js`).
- `api/client.js`는 HttpOnly 쿠키, 메모리 CSRF, 오류, 파일 다운로드를 처리한다. 프론트는 Redis에 직접 연결하지 않는다.
- 메인 카드·막대·도넛·스파크라인, 채팅 답변의 표/차트는 실제 수치로 그린다. 누락값은 0으로 만들지 않는다.
- 리포트는 조건 확인 → 명시적 생성 → 서버 상태 조회 → 저장된 PDF/DOCX/XLSX 다운로드 순서다. 브라우저에서 가짜 파일이나 완료 상태를 만들지 않는다.
- 관리자 페이지의 기존 배너·사이드 메뉴·표·모달에 회원/기사/감사/수집 기록 API를 연결한다.
- 소셜 로그인 버튼·전용 가입/오류 화면·프론트 OAuth 연결 코드는 제거했다. 이메일 로그인을 사용하며 백엔드 OAuth 계약은 변경하지 않았다.

## 대시보드 지표 기준 결정 (#121 / PR #122)

QA 담당자 요청에 따라 기존 F-2의 주요 지표 최근 3개월 기준을 최근 12개월로 변경했다. 대한민국 수출입 현황의 기간을 수출액·수입액·무역수지의 전년 대비 표시와 맞추기 위한 변경이다.

- 주요 지표는 최신 공개 월까지 12개월 합계이며 비교 대상은 전년 동일 12개월이다. 수출액·수입액은 증감률, 무역수지는 금액 차이(억 USD)를 표시한다. 기존 무역수지 카드의 별도 월간 지표인 `전월 수출 증감`은 이 기준에 맞춰 교체했다.
- UN 데이터 카드의 한국 순위는 제공 데이터에 해당 순위 개념이 없어 제거하기로 한 QA 결정이다. 수출 상위 품목 카드의 순위나 3·6·12개월 조회 버튼을 제거하는 변경은 아니다.

근거: #121의 메인 탭 3번(최근 12개월·전년 대비)과 4번(UN 순위 제거)에 대한 요청. 이 기준은 이전 F-2 주석보다 우선한다.

## 검증

### 메인 조회 캐시 (#130)

- 메인 순위·추이 요청은 화면이 마운트된 동안 메모리에 최대 64개, 응답 완료 시점부터 5분간 보관한다. 3·6·12개월 전환 시 유효한 응답과 진행 중인 동일 요청을 재사용한다. 12개월 카드와 품목 표도 같은 순위 요청을 공유한다.
- 계정 ID·관심정보 버전/품목/국가·공개 데이터 버전이 바뀌면 캐시 객체를 교체하고 이전 요청을 취소한다. 공개 데이터 버전은 `/data/availability`를 60초마다 조회해 확인한다. 화면을 떠나면 캐시는 폐기하며, 브라우저 저장소에는 보관하지 않는다.
- 교역국 원그래프도 같은 계정·관심정보·공개 버전을 재조회 기준으로 사용한다. 같은 월의 데이터 정정 시 표와 함께 다시 조회하며, 이전 버전의 늦은 응답은 무시한다. 버전은 클라이언트 재조회 키로만 쓰고 API 요청 본문에는 추가하지 않는다.
- 기준 월·버전의 주기 조회가 실패하면 마지막 성공 값을 유지하고 다음 1분 조회를 계속한다. 첫 조회부터 실패한 경우에만 기준 월 오류·재시도를 표시한다. 같은 버전으로 복구되면 통계 캐시를 비우지 않으며, 성공 응답에서 실제 버전 변경을 확인하면 초기화한다.
- 활성 조회는 캐시 만료 시 백그라운드에서 갱신하며, 동일 조건의 마지막 성공 결과를 화면에 유지한다. 갱신 실패 시 기존 데이터와 영역별 오류·재시도를 함께 보여 주고, 재시도 중에도 데이터를 유지하며, 영역별 `갱신 중` 안내(`role=status`, `aria-busy`)를 표시한다. 갱신이 완료되거나 실패하면 진행 안내를 제거한다. 계정·관심정보·버전 또는 조회 조건이 달라진 경우에는 이전 조건의 데이터를 표시하지 않는다. 실패 응답 자체는 캐시하지 않는다. 기간 전환으로 취소된 구독자는 늦은 응답을 화면에 반영하지 않는다.
- 수출 상위 품목의 순위·금액은 먼저 표시하고 그래프에만 별도 로딩 표시를 둔다. 그래프 오류가 나도 카드와 상세보기 링크는 유지한다.
- 그래프는 순위 응답의 품목과 실제 적용된 `conditions.country_codes`로 조회한다. 관심 국가만 등록한 사용자도 조회할 수 있도록 그래프 품목을 다시 관심 품목으로 제한하지 않는다.
- 공유 순위의 재시도·성공은 카드와 표에 함께 전달해 오류 상태와 만료 타이머를 갱신한다. 일부 그래프만 성공했다고 실패한 나머지 그래프를 자동 반복 요청하지 않는다.
- `npm run test:dashboard`: 실제 Dashboard와 모의 API로 기간 재방문 시 요청 0회, 중복 요청 병합, 만료, 조건·계정·데이터 버전 변경, 늦은 응답, 오류 복구를 검증한다.

```powershell
npm test
npm run lint
npm run build
npm run test:dashboard
npm run test:integration
npm run test:review
```

`npm test`는 API 연결, 응답 변환·검증, 역할, 화면 간 조건 전달 및 요청 ID를 검증한다. 제거된 소셜 로그인 흐름의 브라우저 검증 스크립트도 함께 제거했다.

`test:integration`과 `test:e2e`는 동일한 실제 로컬 연동 검사다. API/worker/Vite, Docker MySQL·Redis, Chrome이 필요하다. `CHROMIUM`으로 다른 Chromium 실행 경로를 지정할 수 있다. 결과와 화면은 `tmp/browser-original/`에 저장한다. 계정·리포트는 로컬 검증용으로 생성한다. 기존 `tests/browser.cjs`와 미사용 목업 데이터 모듈은 디자인 참고 자료이며 현재 검증/실행 진입점에 연결하지 않는다.

기존 프론트에 없던 별도 키워드 차단 편집 화면은 새로 만들지 않았다. 차단 API와 DB 저장 구현은 유지하며, 기존 알림 설정에 편집 UI를 추가할지는 팀의 화면 범위로 정하면 된다.

최근 알림 팝오버는 알림 목록 조회·읽음 저장을 사용한다. 별도의 팝업 배달 조회/확인 API 연결은 후속 작업이며, 팝업 확인과 읽음은 서로 다른 상태다. `test:review`는 실제 로컬 로그인 뒤 오류·지연 응답을 주입하여 채팅 재시도와 리포트 전환 회귀를 검증한다.
