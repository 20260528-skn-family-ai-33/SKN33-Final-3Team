# 단신속보 로컬 회귀 검증

저장소 루트에서 기존 테스트 환경으로 실행합니다.

```bash
python -B backend/tests/shortnews_offline/run_tests.py --repo .
```

네트워크·실제 설정 읽기·원격 DB·운영 Chroma 접근을 차단하고 임시 SQLite·Chroma 및 합성 입력을 사용합니다.
시험 로그와 XML은 시스템 임시 폴더에 저장합니다. `--evidence-dir`로 별도 결과 폴더를 지정할 수 있습니다.
내부 애플리케이션 모듈은 이 체크아웃의 실제 소스를 사용합니다. LLM·임베딩·HTTP 응답은 가상 입력입니다.
실제 스케줄러 시작은 가상 작업으로만 구성된 지정 시험 2건에 한해 허용하고 종료를 확인합니다.
단신 워커의 네이티브 프로세스 시험 4건은 실행 전에 제외합니다. 실제 MySQL 8건과 구형 스키마 관리자 시험 1건은 건너뜁니다.
MySQL/RDS·Windows·서비스 설치 검증을 대신하지 않습니다. pytest와 애플리케이션 의존성이 설치된 환경이 필요하며 자동 설치하지 않습니다.

기본 목록에는 `test_news_embed_rebuild.py`도 포함됩니다. client를 주입하지 않는 기본 실행 경로에서 전체 재임베딩·동일 입력의 일반 갱신 재사용·모델/차원 변경·네 출처 보존·숨김/삭제 기사·본문 누락 상태·dry-run 파일/DB 무변경과 계획 일치·실패 종료코드·본문 게시 복구를 검증합니다. 키워드 실패 뒤 본문만 게시된 부분 완료도 별도로 확인합니다.

모델 전환 뒤 실제 단신 파이프라인을 실행하여 분류·공통 모델의 API 요청과 저장 벡터·새 키워드·단계별 usage를 대조합니다. 키워드는 실제 임베딩 오류·두 번째 배치 실패·잘못된 벡터·저장 검증·핸들 종료·포인터 교체 오류에서 기존 레코드 보존을 확인합니다. 구축 중 reader와 전환 후 기존 reader, 빈 세대 게시, 같은 설정 재시도 및 구형 주입 client의 이름 교체 복원도 검사합니다.

차원 메타데이터가 없는 기존 키워드의 실제 차원, 메타데이터와 실제 벡터의 불일치, 비었지만 차원이 바인딩된 컬렉션도 검증합니다. 차원만 변경 → 본문 게시·키워드 재구축 실패 → 후속 단신 PARTIAL·일반 키워드 실행 실패·검색의 제공자 호출 전 거부 → 키워드만 재구축 재시도 → 정상 검색·단신 SUCCESS까지 확인하고, 실패 중 기존 키워드 데이터와 메타데이터가 보존되는지 대조합니다.

기본 목록은 `test_news_keyword_lifecycle.py`와 `trade_news/`의 `test_common_news_vector.py`·`test_vector_resource_contract.py`도 함께 실행합니다. lifecycle에는 차원이 확인되는 컬렉션 모형을 사용한 검색 중단·소유권 검증과 게시 뒤 정리 실패 시 키워드 단계 호출 검증을 포함합니다. 분리된 공통 임베딩 사용량도 별도로 검증합니다.

실제 SQL·Chroma를 사용하는 lifecycle 시험은 구형/세대 저장소의 writer 교차 실행과 최신 DB 집계 반영, 대기 중 포인터 전환 뒤 오래된 client 거부·재개방을 확인합니다. 취소와 close/dispose 오류를 동시에 주입해 원래 예외 객체·소유권·기존 포인터를 확인하고, 본문 실패 상태 기록과 단신 최종 보고서 저장도 실패시켜 취소가 가려지지 않는지 검사합니다. 키워드 배치 쓰기 전/후·검증·종료·ready 기록·포인터 교체 전/후 오류에서 이전 키워드 보존 → 재시도 → 검색·단신 갱신 성공까지 연결합니다.

사용량 기록은 분류·공통 임베딩 및 분석 LLM 각각에 정상 응답/타임아웃/취소와 sink 실패를 조합합니다. 단신의 실제 SQL·Chroma 갱신 경로에서도 본문/키워드 SDK 취소와 사용량·진행·최종 보고서 저장 실패를 함께 주입하고, 원래 취소 객체 보존 → 다음 실행 성공 → 본문·키워드 검색을 확인합니다. 호출자가 다른 예외를 처리하는 중 실행했더라도 새 종료 실패를 무시하거나 정상 실행을 취소로 오인하지 않는지 검사합니다.
